طراحی پایه را این‌طور قفل می‌کنیم.

## هدف پایه
یک **کورس تعاملی فارسی** روی GitHub Pages با این ویژگی‌ها:

- مفاهیم فیزیک سنجش از دور را تعاملی یاد بدهد
- روی هر فرمول کلیک شود و هر جزء جداگانه توضیح داده شود
- ریاضیات از پایه (تا حد لازم برای فهم فرمول‌ها) پوشش داده شود
- پیشرفت فقط روی دستگاه (localStorage) — ساده و اختیاری
- افزودن درس جدید، صفحه جدید، امتحان، نمونه سؤال و لاب **فقط با اضافه کردن فایل** ممکن باشد
- بدون نام استاد یا منبع خاص

نام پروژه: **RS-Physics-Course**

---

## استک نهایی

| لایه | انتخاب | دلیل |
|------|--------|------|
| فریم‌ورک | **Astro** | خروجی کاملاً استاتیک، مناسب Pages، MDX عالی |
| تعامل | **React islands** | فقط لاب و فرمول تعاملی hydrate می‌شوند |
| محتوا | **MDX + Content Collections** | درس = فایل، نه کد |
| فرمول | **KaTeX** + کامپوننت خودمان | کلیک روی جزء |
| استایل | **Tailwind** + فونت وزیرمتن | RTL تمیز |
| پیشرفت | `localStorage` | ساده، بدون بک‌اند |
| استقرار | GitHub Actions → `gh-pages` | یک‌بار تنظیم |

این استک برای «کورس پژوهشی تعاملی» بهترین تعادل بین سادگی افزودن محتوا و قدرت تعامل است.

## مدل محتوا (مهم‌ترین بخش برای گسترش آسان)

### ۱. درس (Lesson)
هر درس یک فایل MDX است. جلوه‌های تعاملی با کامپوننت فراخوانی می‌شوند:

```mdx
---
title: "تابش جسم سیاه"
order: 3
summary: "قانون پلانک، وین و استفان-بولتزمن"
prerequisites: ["derivatives", "exponentials"]
---

## مقدمه
...

<Formula id="planck" />

<MathCallout primer="exponentials">
  اگر با تابع نمایی راحت نیستی، اول این بخش را ببین.
</MathCallout>

<Lab id="blackbody" />

<Quiz id="blackbody-basics" />
```

اضافه کردن درس جدید = فقط ساخت یک فایل MDX جدید در `content/lessons/`.

### ۲. فرمول تعاملی (هسته یادگیری)
هر فرمول به‌صورت داده ساختاری تعریف می‌شود:

```ts
// content/formulas/planck.ts
export const planck = {
  id: "planck",
  title: "قانون پلانک",
  latex: "B_\\lambda(T) = \\frac{2hc^2}{\\lambda^5}\\frac{1}{e^{hc/\\lambda kT}-1}",
  parts: [
    {
      id: "B",
      latex: "B_\\lambda(T)",
      name: "درخشندگی طیفی",
      explanation: "مقدار انرژی تابشی در واحد زمان، واحد سطح، واحد زاویه فضایی و واحد طول‌موج."
    },
    {
      id: "h",
      latex: "h",
      name: "ثابت پلانک",
      explanation: "۶٫۶۲۶×۱۰⁻³⁴ ژول‌ثانیه. ارتباط انرژی فوتون با بسامد."
    },
    {
      id: "c",
      latex: "c",
      name: "سرعت نور",
      explanation: "۳×۱۰⁸ متر بر ثانیه در خلأ."
    },
    // ... بقیه اجزا
  ],
  derivationNotes: "از آمار Bose-Einstein برای فوتون‌ها به دست می‌آید.",
  relatedLabs: ["blackbody"],
  relatedMath: ["exponentials", "derivatives"]
};
```

کامپوننت `<Formula id="planck" />`:
- فرمول را با KaTeX رندر می‌کند
- روی هر نماد می‌توان کلیک/لمس کرد
- پنل کناری یا پایین، نام + توضیح همان جزء را نشان می‌دهد
- لینک به پیش‌نیاز ریاضی و لاب مرتبط دارد

این الگو برای **همه** فرمول‌ها (ماکسول، کپلر، BRDF، NDVI، وین، استفان و ...) یکسان است.

### ۳. ریاضیات پایه
پوشه `math-primers/` درس‌های کوتاه و هدفمند دارد:

- مشتق و مفهوم نرخ تغییر
- انتگرال به‌عنوان جمع
- بردار و حاصل‌ضرب خارجی (برای نیروی لورنتس)
- تابع نمایی و لگاریتم
- مختصات قطبی (برای مدار)

هر جا در درس فیزیک نیاز باشد، با `<MathCallout>` به همان پرایمر لینک می‌شود. این‌طور ریاضیات از پایه و «درجا» یاد داده می‌شود، نه به‌صورت کورس جدا و خشک.

### ۴. لاب‌ها
ثبت در یک رجیستری:

```ts
// components/Lab/registry.ts
export const labs = {
  wave: () => import("./WaveLab.tsx"),
  blackbody: () => import("./BlackbodyLab.tsx"),
  orbit: () => import("./OrbitLab.tsx"),
  // ...
} as const;
```

اضافه کردن لاب جدید = یک کامپوننت + یک خط در رجیستری + اشاره در MDX درس.

### ۵. آزمون و نمونه سؤال
فایل‌های داده در `content/exams/` و `content/quizzes/`. صفحه مربوطه فقط آن‌ها را می‌خواند. افزودن امتحان جدید = فایل جدید.

## جریان یادگیری پیشنهادی (برای طراحی UI)

1. **فهرست درس‌ها** (صفحه اصلی)
2. داخل هر درس:
   - متن مفهومی
   - فرمول کلیک‌پذیر
   - در صورت نیاز → پرایمر ریاضی
   - لاب تعاملی
   - چند سؤال کوتاه
3. بخش جدا: **ریاضیات پایه**
4. بخش جدا: **آزمون‌ها و نمونه سؤال‌ها**
5. پیشرفت (اختیاری): تیک «خواندم» / «لاب را انجام دادم» فقط در localStorage

هیچ احراز هویت و هیچ سروری نیست.

## مستند گسترش (docs/ADDING-CONTENT.md)

این فایل باید دقیقاً بگوید:

- چطور درس جدید اضافه کنی (قالب frontmatter + مثال)
- چطور فرمول جدید تعریف کنی (ساختار `parts`)
- چطور لاب جدید ثبت کنی
- چطور آزمون بسازی
- قرارداد نام‌گذاری slugها
- چطور پیش‌نیاز ریاضی را لینک کنی

با این سند، تو (یا هر کس دیگری) می‌تواند بدون دست زدن به هسته، محتوا اضافه کند.

## داده‌های فعلی که از قبل داریم

از جزوه قبلی می‌توانیم این اسکلت را پر کنیم (بدون نام منبع):

1. مقدمه و تعاریف سنجش از دور  
2. موج الکترومغناطیسی و خواص موج  
3. معادلات ماکسول و تابش  
4. برهم‌کنش با ماده (جذب، پراکندگی، بازتاب، BRDF)  
5. تصحیح اتمسفری و مسیر تابش  
6. مکانیک مداری ماهواره  

به‌همراه فرمول‌های کلیدی (پلانک، وین، استفان، ماکسول، کپلر، NDVI، داپلر و ...) و لاب‌های متناظر.

## قدم بعدی (بدون ساخت کامل اپ)

اگر این طراحی را تأیید کنی، قدم منطقی بعدی این است:

1. اسکلت خالی Astro + Content Collections + یک درس نمونه + یک فرمول تعاملی کامل  
2. فایل `ADDING-CONTENT.md`  
3. تنظیم deploy به GitHub Pages  

بعد تو می‌توانی درس‌ها و فرمول‌ها را یکی‌یکی اضافه کنی.

اگر جایی از این طراحی را می‌خواهی تغییر بدهی (مثلاً بدون MDX و فقط TypeScript، یا ساختار فصل‌بندی متفاوت)، بگو تا قبل از پیاده‌سازی پایه را اصلاح کنیم.
